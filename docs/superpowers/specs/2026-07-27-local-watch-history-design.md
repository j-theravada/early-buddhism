# ローカル視聴履歴と再生位置保存 設計仕様

## 状態

- 2026-07-27 方針承認済み
- ログインを追加せず、同じブラウザの `localStorage` に保存する

## 目的

法話動画を再生した利用者が、同じブラウザで視聴履歴を確認し、未視聴部分がある動画を前回位置から再開できるようにする。

現在のYouTubeプレイヤーは、利用者が再生ボタンを押すまでiframeを読み込まない。この遅延読み込みを維持し、再生位置の取得に必要なYouTube IFrame Player APIも再生開始後だけ読み込む。

## 成功条件

- 30秒以上再生した法話を視聴履歴へ保存する。
- 再生中は15秒ごと、一時停止時、終了時、ページ離脱時に最新位置を保存する。
- 未視聴部分がある法話を再び開いた時は、前回位置の3秒前から再生する。
- 90%以上再生した場合、または残り30秒以内になった場合は視聴済みとする。
- 視聴済みの法話は履歴に残すが、次回は先頭から再生する。
- `/history` で新しい順に最大200件の履歴を確認できる。
- 動画を再生しないページではYouTube iframeとIFrame Player APIを読み込まない。
- localStorageやYouTube APIが利用できない場合も、通常の動画再生と詳細閲覧を妨げない。

## 非対象

- ログイン、ユーザーアカウント、端末間同期
- サーバー、Turso、SQLite、GA4への個人別視聴履歴の保存
- YouTube側の視聴履歴との同期
- おすすめ動画や視聴傾向の分析
- 履歴データのエクスポート

## 検討した方式

### 1. YouTube APIを遅延読み込みして位置を保存（採用）

再生開始後だけYouTube IFrame Player APIを読み込み、再生中の位置と動画時間を取得する。15秒間隔と状態変化時だけlocalStorageへ書き込むため、追加の通信・CPU・ストレージ使用量を小さくできる。

### 2. 再生ボタンのクリックだけを履歴として保存

YouTube APIが不要で最も軽いが、再生位置と視聴完了を判定できない。今回承認された「続きから再生」を満たさないため採用しない。

### 3. YouTube iframeをページ表示時からAPI付きで読み込む

実装は単純になるが、動画を再生しない利用者にもYouTubeのiframeとAPIを読み込ませる。現在の遅延読み込みによる性能・プライバシー上の利点を失うため採用しない。

## 保存データ

保存キーは `early-buddhism:watch-history:v1` とする。値は法話IDをキーとする履歴オブジェクトで、各項目に次を保存する。

- `talkId`: 法話ID
- `title`: 履歴画面に表示する保存時点のタイトル
- `thumbnailUrl`: 保存時点のサムネイルURL
- `positionSeconds`: 最終再生位置
- `durationSeconds`: 取得できた動画時間。未取得時は `null`
- `lastWatchedAt`: 最終保存日時
- `completed`: 視聴済みか

履歴画面のために全法話データをブラウザへ送らず、表示に必要な最小限のスナップショットを履歴内に保存する。タイトルやサムネイルが後日変更されても、詳細ページへ移動すれば最新情報を表示する。

書き込み時に同じ法話IDの項目を更新し、`lastWatchedAt` の新しい順で最大200件だけ残す。推定容量は数十KBであり、通常のlocalStorage上限に対して十分小さい。

## プレイヤーのデータフロー

1. 詳細ページはプレイヤーへ法話ID、タイトル、サムネイルURL、YouTube埋め込みURLを渡す。
2. 初期表示では既存どおりサムネイルと再生ボタンだけを表示する。
3. 再生ボタンを押した時に、保存済みの未完了位置を読む。
4. 30秒以上の保存位置があれば、その3秒前を開始位置とする。保存位置が30秒未満、または視聴済みなら先頭から始める。
5. YouTube IFrame Player APIを遅延読み込みし、プレイヤーを開始する。
6. 再生中だけ15秒間隔のタイマーを動かし、位置と動画時間を保存する。
7. 一時停止、終了、ページ非表示、コンポーネント破棄時にも保存を試みる。
8. タイマーとイベントリスナーを必ず解放する。

文字起こし内の時刻リンクなど、利用者が明示的な再生位置を選んだ場合は、その位置を履歴の再開位置より優先する。

YouTube APIスクリプトはページ内で一度だけ読み込む共有loaderを使う。複数回の初期化や競合を避け、既存の `window.onYouTubeIframeAPIReady` がある場合も壊さない形で準備完了を通知する。

## 履歴画面

- URLは `/history`
- グローバルナビゲーションに「視聴履歴」を追加する
- 新しい順にタイトル、サムネイル、最終視聴日時、再生位置、視聴済み状態を表示する
- 未完了項目のリンク文言は「続きから再生」、完了項目は「もう一度見る」とする
- 履歴がない場合は説明と「動画一覧を見る」リンクを表示する
- localStorageはサーバー描画時に読めないため、ページの枠をサーバーで描画し、履歴一覧をClient Componentとしてマウント後に表示する
- 個人端末内の状態で内容が変わるページなので、サイトマップには含めず `noindex` とする

初回実装では個別削除、全件削除、検索、絞り込みを追加しない。

## エラー処理

- localStorageへのアクセス失敗、容量超過、不正なJSONは例外を画面へ伝播させない。
- 不正な履歴項目は読み込み時に除外し、正常な項目だけを表示する。
- YouTube APIの読み込みに失敗した場合は、位置記録を無効にして通常のiframe再生へフォールバックする。
- 動画時間を取得できない場合は位置だけを保存し、視聴済みとは判定しない。
- ページ離脱時の保存は失敗しても遷移を止めない。

## テスト戦略

挙動変更は失敗するテストを先に追加してから実装する。

### localStorage境界

- 空の保存領域を空履歴として読む。
- 不正なJSONと不正な項目を安全に除外する。
- 同じ法話IDを重複させず更新する。
- 履歴を最終視聴日時の新しい順に並べる。
- 200件を超えた古い履歴を削る。
- localStorageが例外を投げても読み書き処理が例外を返さない。

### 再生状態

- 30秒未満の再生を履歴に保存しない。
- 15秒間隔、一時停止、終了、ページ離脱時に保存する。
- 90%以上または残り30秒以内を視聴済みと判定する。
- 未完了の保存位置から3秒戻って再開する。
- 視聴済み、30秒未満、動画時間外の位置は先頭から再生する。
- 文字起こしから指定された位置を履歴より優先する。
- 再生停止後に保存タイマーを解放する。

### 表示

- 履歴を新しい順に表示する。
- 未完了と視聴済みでリンク文言を切り替える。
- 空履歴の案内を表示する。
- `/history` を `noindex` にし、サイトマップへ追加しない。
- グローバルナビゲーションから履歴画面へ移動できる。

### 回帰確認

- JavaScript無効時も既存の詳細本文とYouTubeリンクを利用できる。
- 再生前はYouTube iframeとIFrame Player APIを読み込まない。
- 既存の再生ボタン、文字起こし時刻リンク、stickyプレイヤーを維持する。
- `bun test`、`bun run lint`、`bun run format:check`、`bun run build` を通す。
